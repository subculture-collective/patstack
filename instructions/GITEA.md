# Gitea agent identity

## Where repositories live (since 2026-11-10)

GitHub `subculture-collective` is the source for every repository in that organization, including copies whose Gitea home is under `PatrickFanella`. Push branches and open pull requests on `github.com/subculture-collective/<name>` with `gh`. Pull requests on those Gitea repositories are turned off. A ready pull request merges itself once its required checks pass and it has no conflicts: a Kvant timer merges as the repository owner's account, so main-branch deploys run. To hold one back, open it as a draft or add the label `hold`. Kvant copies GitHub to Gitea every minute, fast-forward only. Deploys are moving to GitHub Actions, which reach the homelab over the tailnet; jobs not yet moved still run on Gitea Actions after that copy. Do not push to these repositories on Gitea; a commit made there is never copied back. Some of them also have a `PatrickFanella/<name>` copy on GitHub that is kept current automatically from the Gitea mirror; do not edit those copies either. Issues for every organization repository, public or private, live on GitHub: open and edit them with `gh`. Their Gitea issues were moved on 2026-11-10, with sub-issues, blocked-by links, milestones and issue types, and Gitea issues are turned off. Each repository with active issues has an organization Project named after it; add new issues to it. Public products also have Discussions on. Local checkouts use GitHub as `origin` and keep Gitea as the fetch-only remote `gitea`, which also selects the agent Git identity below. A fresh clone from GitHub has no `gitea` remote, so set the identity with command-local `-c user.name=... -c user.email=...`. Repositories that exist only on Gitea keep the Gitea workflow: push branches to Gitea, open pull requests and issues with `tea`, and act as `subcult-agent`.

Use `subcult-agent` for agent actions on `https://git.subcult.tv` on every device. The default `tea` login and Gitea HTTPS Git credential helper select this account. When a command accepts a login, pass `--login subcult-agent`; names such as `open-pilot`, `subcult`, and `patrickfanella` may still authenticate as the human operator.

Before a Gitea write, verify `tea api --login subcult-agent /user` returns `login: subcult-agent`. Before committing agent work, inspect `git var GIT_AUTHOR_IDENT` and `git var GIT_COMMITTER_IDENT`. Gitea repositories normally inherit `SUBCULT Agent <info@subcult.tv>` from a conditional Git include. If a worktree or environment overrides it, use command-local `-c user.name='SUBCULT Agent' -c user.email='info@subcult.tv' -c commit.gpgsign=false` for the agent commit. Do not sign agent commits with the human operator's key.

Use the installed Gitea HTTPS credential helper for pushes. Fleet Git URL rules route Gitea SSH remotes through HTTPS without changing repository remotes. Do not bypass these rules with a human SSH key or recover a permission failure by falling back to a human token. Report the missing access and obtain the appropriate repository grant.

The user promoted `subcult-agent` to Gitea site administrator and authorized the API `write:admin` scope on October 3, 2026. Its `agent-actions` team still explicitly enrolls the original 69 `subculture-collective` repositories, but site administration also permits access beyond that team. The account remains distinct from the human operator. The user subsequently authorized full read/write API access, including administration. All six device tokens now use Gitea’s `all` scope, covering every API category, including users, organizations, packages and administration. Token creation on this instance requires account authentication; a fully scoped personal access token alone returns `401 auth required` at that endpoint. Use the agent identity for authorized work and report a missing token scope instead of falling back to a human token.

Device tokens are stored in private `tea` configuration. Do not print them, put them in remote URLs, copy them into project files, or revoke retained human/service credentials during routine agent work. Configuration deployment and rollback receipts live in `~/.local/state/gitea-agent/` on each host. Switchyard stays on its `open-pilot` runtime identity by the user's explicit instruction; do not replace its runtime credential or identity settings as part of a general fleet default change.
